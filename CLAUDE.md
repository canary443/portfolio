## What this project is
Personal portfolio site **AimworkSpace** for a full stack developer (nickname: aimwork, tg @sickbuddy, email contact@leet-cheats.xyz). Next.js 15 (App Router) + React 19 + TypeScript, app at the repo root:
- `app/page.tsx` — tiny server wrapper: reads the shared content and the `zx_lang` cookie, then renders `app/site.tsx`
- `app/site.tsx` — the public site itself, a client component (dark, Hyperstudio-style, EN with RU toggle). All page markup lives here, so this is the file to edit for site UI work
- `app/layout.tsx` — `<html lang>` from the same language pick as the page, static metadata (og / twitter preview, ProfessionalService json-ld), the two font preloads, `@vercel/analytics`
- `app/admin/page.tsx` — password-gated admin panel that edits all content
- `app/api/admin/session/route.ts` — login / session check / logout; passphrase comes from the `ADMIN_PASSWORD` env var, session is an httpOnly cookie, rate limiting is per-IP server-side
- `lib/data.ts` — shared data layer (types, defaults, localStorage cache under key `zx_data_v2`, plus `loadRemote` / `saveRemote`)
- `app/api/content/route.ts` — shared content on Vercel Blob (`site.json`); GET is public, PUT needs the admin cookie
- `lib/content.ts` — the server-side read of `site.json`, used by the page and by that route. Deliberately uncached, the comment on top says why
- `app/api/upload/route.ts` — admin-only media upload to Supabase storage; takes a data url or a link to copy, returns a public url
- `lib/img.ts` — the client side of media: `uploadMedia`, `importUrl`, `inStorage`, `shrinkImage`, `fileToDataUrl`
- `lib/lang.ts` — `pickLang(cookie)`, shared by `app/page.tsx` and `app/layout.tsx`
- `lib/session.ts` — admin session token sign / check, shared by the session, content and upload routes
- `components/fx/` — the two optional cursors: `PixelTrailCursor.tsx` (webgl) and `TargetCursorFx.tsx`. The hero layers that used to live here (`HeroFx`, `HeroArtVideo`, `HeadlineReveal`) went with the hero on 2026-07-29.
- `components/BrandIcons.tsx` — brand logos as inline SVG; `app/fonts.css` + `public/fonts/*.woff2` — the self-hosted fonts
- `app/robots.ts` / `app/sitemap.ts` / `app/llms.txt/route.ts` — robots.txt (disallows `/admin`, `/api` and `?preview=`), the one-url sitemap, and the whole site as plain text for assistants

## Key implementation facts
- Content model lives in `lib/data.ts` DEFAULTS. The admin PUTs the whole object to `/api/content`, which stores `site.json` in the Vercel Blob store `portfolio-content` (private), and mirrors it into localStorage as a cache. PUT also checks the shape of the json (the text fields and the three lists) and refuses a body over 4mb. The public page no longer waits for a fetch: `app/page.tsx` reads the content server side (`lib/content.ts`) and passes it in as props, then `app/site.tsx` re-pulls with `loadRemote()` on window focus. The admin also writes a `zx_preview` key on every change and the site picks it up through the `storage` event, so a tab opened at `/?preview=1` (the admin preview iframe, or its "Open in tab" link) is a live preview. First admin visit with an empty store uploads the local content (untouched demo content is skipped), so nothing is lost. HANDOFF.md holds the Supabase plan if a real database is ever needed.
- There is no data cache around the blob read on purpose: the Next data cache refuses anything over 2mb and `site.json` used to be ~3.8mb, so the failure came back as an unhandled rejection on every request. The media has moved to storage since (see the media bullet), so that blocker is gone and a cached read is a small change away - `lib/content.ts` says the same at the top.
- Media: every upload (photo, gif, video) goes through `/api/upload` to Supabase storage (`SUPABASE_URL` + service role or anon key) and lands in the content JSON as a public url. The route is admin-only. It takes a data url from the browser or a link to copy - a pasted cdn link is fetched server side and stored, and only public http(s) targets are allowed (no localhost, no private ranges). It caps a file at 25mb, allows jpeg/png/webp/svg/gif/mp4/webm only, and takes the extension from the mime, so a caller can not name the file. `lib/img.ts` (`uploadMedia`, `importUrl`, `inStorage`) is the client side of it; with Supabase not configured the upload falls back to keeping the base64. Old media used to sit inside `site.json` as base64, about 3.8mb, right under the 4mb save cap - the admin settings page has a "Move N files to storage" button that uploads whatever is still inline and then saves once. Checked 2026-07-25: it has been pressed, the live file is down to ~13kb of urls with nothing inline left. Keep new media on the upload path so it stays that way. A daily Vercel cron (07:00, `vercel.json`) hits `/api/keepalive` so the free Supabase project is not paused.
- `ADMIN_PASSWORD` and `ADMIN_SESSION_SECRET` are set in `.env.local` locally and in Vercel env vars. Do not write the literal passphrase into any committed file; ask the owner if you need it. The owner plans to rotate it before the real launch.
- Deploy: Vercel project `portfolio` (team `t3rmynals-projects`), live on https://aimwork.space (domain registered at Vercel). `CRON_SECRET` is set for Production, so `/api/keepalive` answers 401 to anyone but the Vercel cron - after changing that var the project has to be redeployed for it to take effect.
- Motion: lenis smooth scroll (lerp .09); Safari gets cheaper compositing (no mix-blend-mode on cursor/grain, lighter blur); `prefers-reduced-motion` is respected everywhere (no lenis, no parallax, fades instead of slides, native cursor).
- The page opens with the About block: the `aboutH` heading as the `<h1>`, the about text through the tiny markdown renderer, the admin gif or photo under it, then the location line. Straight after it the two partner logos (`public/assets/leet-cheats.svg`, `binware.svg`) sit behind a bare hairline with no label. The hero (its webgl backgrounds, the ascii cat, the headline reveal, the video sound pass) was deleted on 2026-07-29 together with the faq, the prices and the footer; `git log` has it if it is ever wanted back.
- Whole blocks can be switched off from the admin settings page: `showServices` (the services cards) and `showStack` (the moving tech stack strip). Both default to true, both are currently off in the live content, and they live in the content json, so they are one click away in either direction.
- The page ends with two full-width links (`.blink` in globals.css): the word `telegram` / `github` large on the left with its brand icon, the handle and a `↗` on the right. Hover wipes a white fill across the row (`clip-path: inset(0 100% 0 0)` → `inset(0)`, .45s) while a second copy of the same row, clipped the same way, carries the black text; reduced motion fades the fill in instead. The nav is fully transparent at the top now - the canvas is flat `#101010`, so any tint there reads as a dark rectangle - and it holds only the wordmark and the language picker, the section links went with the sections.
- Fonts are self-hosted: `app/fonts.css` declares plain `@font-face` rules over the 12 woff2 files in `public/fonts` (Satoshi 400/500, plus the Cyrillic companions Onest / Carlito / Jost, latin + cyrillic subsets, ~217kb total; the layout preloads only the two Satoshi faces of the first paint). The family names stay `'Satoshi'`, `'Onest'`, `'Carlito'`, `'Jost'` because the runtime font stacks in `app/site.tsx` and the admin are built from those exact strings - do not rename them. The Cyrillic companion for RU is admin-selectable (`fontRu`: Onest default), and every interface string can also override it per key via `i18nFontRu` (chips under the RU inputs in the admin Interface text page).
- Brand icons are inline SVG in `components/BrandIcons.tsx` (14 Simple Icons paths, CC0). Nothing loads from a third-party CDN at runtime any more: both Fontshare/Google Fonts and cdn.simpleicons.org are gone, because they are slow or blocked for the Russian audience. The only outside calls left are the Supabase media urls.
- SEO and headers: `app/robots.ts` allows everything but `/admin`, `/api` and `/*?preview=`, and names the AI crawlers (GPTBot, ClaudeBot, PerplexityBot and friends) in an explicit allow group - a portfolio wants to be quotable. `app/sitemap.ts` lists the single url. `app/llms.txt/route.ts` serves about / services / work / team projects as plain text, built from the live content so it cannot drift (1h cache). `app/layout.tsx` carries the canonical `/` (so the admin's `/?preview=1` tab is never a second page), `index, follow` plus the googlebot preview limits, og/twitter with `og:locale` en_US and ru_RU as the alternate, static ProfessionalService json-ld, and the Yandex Webmaster meta tag read from `YANDEX_VERIFICATION` (set in all three Vercel environments, a public value, needs a redeploy to change). Google is verified the other way, as a **domain property over DNS**: a TXT record on the apex of the Vercel DNS zone holding `google-site-verification=...` (`vercel dns ls aimwork.space`), which covers every subdomain and needs no deploy. `GOOGLE_SITE_VERIFICATION` is wired in the layout but intentionally unset - it is only there if a url-prefix property is ever added on top. Both properties were registered 2026-07-26; submitting the sitemap in each console is manual. `@vercel/analytics` is mounted in the body. No hreflang on purpose - both languages live on one url. `next.config.mjs` sends HSTS, nosniff, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, a `Permissions-Policy` and `X-Robots-Tag: noindex, nofollow` on `/admin` (all verified live). The CSP is still **report only**; its comment asks for local fonts and icons before it blocks, and that has landed, so the rules as written now match what the site loads - flipping the header name is the last step and needs a browser check first.
- Bot protection: Vercel BotID (`botid`) guards `POST /api/admin/session`, the only write on the site with no cookie behind it. `next.config.mjs` is wrapped in `withBotId`, which adds same-origin rewrites so the challenge script is served from `aimwork.space/149e9513-.../c.js` and proxied server side - no third-party host is called from the browser, same rule as the local fonts and icons. The client half is `<BotIdClient>` in `app/admin/layout.tsx`, so it ships on `/admin` only: the public page has zero botid code and makes zero extra requests (the script is lazy anyway, it loads on the first protected fetch). The route calls `checkBotId()` before it looks at the password and answers 403 to a bot, but a check that *throws* counts as human on purpose - an outage in the bot service must never lock the owner out, and the passphrase plus the per-IP lockout still guard the route. Level is BotID Basic (free on every plan); Deep Analysis needs Pro and `checkLevel: 'deepAnalysis'` set on **both** the client and the route, or every login fails.
- Accessibility is part of the design here, do not regress it: every hit target is a real button on the `.bare` reset (globals.css) - project cards (a `.card-hit` button inside the card), the language picker, the modal close, carousel arrows and modal dots. The modal is `role="dialog"` + `aria-modal` with a focus trap and focus handed back to the card. The page keeps exactly one `<h1>` (the About heading).
- Card media is `components/MediaCarousel.tsx` (embla): `preload="metadata"` so the first video frame paints, a file that fails to load is reported up (`badMedia` in `app/site.tsx`) and dropped, so the card falls back to the next photo; a video with no metadata after 8s counts as broken. Playback only runs while the card is on screen (IntersectionObserver) and never under reduced motion, and the auto advance can not get stuck on a video that is not playing.
- Tests: `npm run test:cursor` and `npm run test:no-magnetic` (plain node scripts in `scripts/`, they read `app/site.tsx` and `globals.css` as text). Run both after touching the cursor or the page markup.
