## What this project is
Personal portfolio site **AimworkSpace** for a full stack developer (nickname: aimwork, tg @sickbuddy, email contact@leet-cheats.xyz). Next.js 15 (App Router) + React 19 + TypeScript, app at the repo root:
- `app/page.tsx` — tiny server wrapper: reads the shared content and the `zx_lang` cookie, then renders `app/site.tsx`
- `app/site.tsx` — the public site itself, a client component (dark, Hyperstudio-style, EN with RU toggle). All page markup lives here, so this is the file to edit for site UI work
- `app/layout.tsx` — `<html lang>` from the same language pick as the page, static metadata (og / twitter preview, ProfessionalService json-ld), the two font preloads, `@vercel/analytics`
- `app/admin/page.tsx` — password-gated admin panel that edits all content
- `app/api/admin/session/route.ts` — login / session check / logout; passphrase comes from the `ADMIN_PASSWORD` env var, session is an httpOnly cookie, rate limiting is per-IP server-side
- `app/api/content/route.ts` — shared content on Vercel Blob (`site.json`); GET is public, PUT needs the admin cookie
- `lib/content.ts` — the server-side read of `site.json`, used by the page and by that route. Deliberately uncached, the comment on top says why
- `app/api/upload/route.ts` — admin-only media upload to Supabase storage; takes a data url or a link to copy, returns a public url
- `lib/data.ts` — shared data layer (types, defaults, localStorage cache under key `zx_data_v2`, plus `loadRemote` / `saveRemote`)
- `lib/img.ts` — the client side of media: `uploadMedia`, `importUrl`, `inStorage`, `shrinkImage`, `fileToDataUrl`, `firstFrame`, `isVideoSrc`
- `lib/lang.ts` — `pickLang(cookie, accept-language)`, shared by `app/page.tsx` and `app/layout.tsx`
- `lib/session.ts` — admin session token sign / check, shared by the session, content and upload routes
- `components/fx/` — hero layers: `HeroFx.tsx` (background + readability scrim), `HeroArtVideo.tsx` (the one loud pass), plus the cursor and headline effects
- `components/BrandIcons.tsx` — brand logos as inline SVG; `app/fonts.css` + `public/fonts/*.woff2` — the self-hosted fonts
- `app/robots.ts` / `app/sitemap.ts` — robots.txt (disallows `/admin` and `/api`) and the one-url sitemap

## Key implementation facts
- Content model lives in `lib/data.ts` DEFAULTS. The admin PUTs the whole object to `/api/content`, which stores `site.json` in the Vercel Blob store `portfolio-content` (private), and mirrors it into localStorage as a cache. PUT also checks the shape of the json (the text fields and the four lists) and refuses a body over 4mb. `app/page.tsx` reads the content server side (`lib/content.ts`) and passes it in as props, so the first paint is already real; `app/site.tsx` re-pulls with `loadRemote()` on window focus. The admin also writes a `zx_preview` key on every change and the site picks it up through the `storage` event, so a tab opened at `/?preview=1` (the admin preview iframe, or its "Open in tab" link) is a live preview. First admin visit with an empty store uploads the local content (untouched demo content is skipped), so nothing is lost. HANDOFF.md holds the Supabase plan if a real database is ever needed.
- There is no data cache around the blob read on purpose: the Next data cache refuses anything over 2mb and `site.json` used to be ~3.8mb, so the failure came back as an unhandled rejection on every request. The media has moved to storage since (see the media bullet), so that blocker is gone and a cached read is a small change away - `lib/content.ts` says the same at the top.
- Media: every upload (photo, gif, video) goes through `/api/upload` to Supabase storage (`SUPABASE_URL` + service role or anon key) and lands in the content JSON as a public url. The route is admin-only. It takes a data url from the browser or a link to copy - a pasted cdn link is fetched server side and stored, and only public http(s) targets are allowed (no localhost, no private ranges). It caps a file at 25mb, allows jpeg/png/webp/svg/gif/mp4/webm only, and takes the extension from the mime, so a caller can not name the file. `lib/img.ts` (`uploadMedia`, `importUrl`, `inStorage`) is the client side of it; with Supabase not configured the upload falls back to keeping the base64. Old media used to sit inside `site.json` as base64, about 3.8mb, right under the 4mb save cap - the admin settings page has a "Move N files to storage" button that uploads whatever is still inline and then saves once. Checked 2026-07-25: it has been pressed, the live file is down to ~13kb of urls with nothing inline left. Keep new media on the upload path so it stays that way. A daily Vercel cron (07:00, `vercel.json`) hits `/api/keepalive` so the free Supabase project is not paused.
- `ADMIN_PASSWORD` and `ADMIN_SESSION_SECRET` are set in `.env.local` locally and in Vercel env vars. Do not write the literal passphrase into any committed file; ask the owner if you need it. The owner plans to rotate it before the real launch.
- Deploy: Vercel project `portfolio` (team `t3rmynals-projects`), live on https://aimwork.space (domain registered at Vercel). `CRON_SECRET` is set for Production, so `/api/keepalive` answers 401 to anyone but the Vercel cron - after changing that var the project has to be redeployed for it to take effect.
- Motion: lenis smooth scroll (lerp .09); Safari gets cheaper compositing (no mix-blend-mode on cursor/grain, lighter blur); `prefers-reduced-motion` is respected everywhere (no lenis, no parallax, fades instead of slides, native cursor).
- The hero art is admin-switchable (`heroArt`): ascii cat `public/assets/kitokat-ascii-fine.avif` (default, rendered from `kitokat-raw.jpg`), braille cat `public/assets/kitokat-braille.avif`, dot-art hands `public/assets/hero-hands.*`, or an upload. an upload comes in two flavours: `custom` runs the picture through the ascii renderer (`lib/ascii.ts`) so it keeps the glyphs-on-black look and is stored in `heroArtCustom` (pasted ascii / braille art goes down the same path), while `media` keeps a photo, gif or video exactly as it is in `heroArtMedia`, with `heroArtMediaPoster` as the still frame for reduced motion. `media` is the only art that is not zoomed to 1.06, so a photo is never cropped. an mp4/webm hero art plays its first pass with sound and then loops muted like a gif (`components/fx/HeroArtVideo.tsx`, switch `heroArtMediaSound`, on by default). browsers refuse to start a video with sound before the visitor has clicked or typed on the page, and that is not something the site can turn off. so a refused start runs as a silent loop and the first gesture restarts the file from frame one with the sound on. clicks, taps and keys always unlock it; scrolling is not permission by spec but chrome accepts a wheel or touch scroll, so a scroll gets a few throttled tries and a refusal falls back to the silent loop with no jump and no stall - the loud pass is always heard whole, never from the middle. reduced motion still gets the still poster and no playback. there is no mute button by the owner's call, so a visitor who wants silence has to mute the tab. partner logos in `public/assets/`.
- The hero background is `heroBg`: `image` (no background layer at all, just the hero art), one of the webgl presets (`pixel-blast`, `dither`, `threads`, `liquid-chrome`, fine pointer + webgl only), or `gif` - an uploaded gif or video (`heroBgGif`) with a still poster (`heroBgGifPoster`) used when the visitor asks for less motion, plus its own opacity (`heroBgGifOpacity`, 10-100). `gif` is plain media, so it also runs on phones and Safari; with no file uploaded it falls back to `image`. `components/fx/HeroFx.tsx` draws the layer and owns the scrim that keeps the headline readable - a gif can be anything, so gif mode veils the middle harder than the webgl ones. Any background other than `image` takes the place of the hero art; a device that can not run the picked webgl effect falls back to showing the art.
- Fonts are self-hosted: `app/fonts.css` declares plain `@font-face` rules over the 12 woff2 files in `public/fonts` (Satoshi 400/500, plus the Cyrillic companions Onest / Carlito / Jost, latin + cyrillic subsets, ~217kb total; the layout preloads only the two Satoshi faces of the first paint). Keep the family names `'Satoshi'`, `'Onest'`, `'Carlito'`, `'Jost'` - the runtime font stacks in `app/site.tsx` and the admin are built from those exact strings. The RU companion is admin-selectable (`fontRu`: Onest default), and every interface string can override it per key via `i18nFontRu` (chips under the RU inputs in the admin Interface text page).
- Brand icons are inline SVG in `components/BrandIcons.tsx` (14 Simple Icons paths, CC0). No third-party CDN is used at runtime (Fontshare, Google Fonts and cdn.simpleicons.org are all gone - they are slow or blocked for the Russian audience). The only outside calls left are the exchange rate api (open.er-api.com, from the browser) and the Supabase media urls.
- SEO and headers: `app/robots.ts` disallows `/admin` and `/api`, `app/sitemap.ts` lists the single url, `app/layout.tsx` carries a real og/twitter description and static ProfessionalService json-ld, and `@vercel/analytics` is mounted in the body. No hreflang on purpose - both languages live on one url. `next.config.mjs` sends HSTS, nosniff, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, a `Permissions-Policy` and `X-Robots-Tag: noindex, nofollow` on `/admin` (all verified live). The CSP is still **report only**; its comment asks for local fonts and icons before it blocks, and that has landed, so the rules as written now match what the site loads - flipping the header name is the last step and needs a browser check first.
- Accessibility is part of the design here, do not regress it: every hit target is a real button on the `.bare` reset (globals.css) - faq rows, project cards (a `.card-hit` button inside the card), the language picker, the modal close, the email copy chip, carousel arrows and modal dots. The modal is `role="dialog"` + `aria-modal` with a focus trap and focus handed back to the card, a closed faq answer is `inert` + `aria-hidden`, the toast is an always-mounted `role="status"` live region.
- Card media is `components/MediaCarousel.tsx` (embla): `preload="metadata"` so the first video frame paints, a file that fails to load is reported up (`badMedia` in `app/site.tsx`) and dropped, so the card falls back to the next photo; a video with no metadata after 8s counts as broken. Playback only runs while the card is on screen (IntersectionObserver) and never under reduced motion, and the auto advance can not get stuck on a video that is not playing.
- Tests: `npm run test:cursor` and `npm run test:no-magnetic` (plain node scripts in `scripts/`, they read `app/site.tsx` and `globals.css` as text). Run both after touching the cursor or the hero markup.
