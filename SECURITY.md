# SECURITY.md

## Current state
- Admin auth is server-side: `POST /api/admin/session` compares the passphrase against the `ADMIN_PASSWORD` env var (timing-safe compare over HMAC digests) and sets an httpOnly cookie (`sameSite: lax`, `secure` in production, 12h lifetime).
- The session cookie is `exp.HMAC(ADMIN_SESSION_SECRET, exp)` — signed with a secret that is independent of the passphrase, so a leaked cookie cannot be used to brute-force the password offline. Expiry is embedded and checked server-side, so a copied cookie stops working after 12h even if the browser keeps it. The client never sees the passphrase or the secret.
- Bot check on the login: `POST /api/admin/session` runs Vercel BotID (`checkBotId()`) before it looks at the password, so a script that cannot produce a real browser signature never reaches the compare and never spends the attempt budget. The client half is `<BotIdClient>` in `app/admin/layout.tsx`, so it ships on `/admin` only and the public page is untouched. `withBotId` in `next.config.mjs` proxies the challenge script through our own domain (`/149e9513-…/c.js`), so no third-party host is called from the browser — the same reason the fonts and icons are local. The check is deliberately **fail-open on error**: a thrown check returns "not a bot", because an outage in the bot service must never lock the owner out. A confident bot verdict is still trusted and answers 403. Detection level is BotID Basic (free on every plan); Deep Analysis needs Pro and `checkLevel: 'deepAnalysis'` set on **both** sides or verification fails.
- Rate limiting: per-IP in the route handler — 3 failed tries → 60s lockout, doubling each time up to a cap. The gate shows only "too many attempts" and a countdown. State is in-memory, so it resets on redeploy and is per-instance on serverless — acceptable for now, see checklist. The map is swept of stale entries so it does not grow unbounded.
- Content lives server-side now: `site.json` in a private Vercel Blob store. `GET /api/content` is public (it is the public site's content anyway), `PUT` needs the admin cookie, rejects a body over 4mb and runs a shape check before writing (the text fields must be text, `services`/`works`/`projects`/`faq` must be lists of objects with a string `id`; unknown keys pass, the model keeps growing). localStorage is only the admin's local cache — the public page no longer reads it.
- Media uploads: `POST /api/upload` needs the admin cookie, caps a file at 25mb and stores only an allowlisted mime (jpeg/png/webp/svg/gif/mp4/webm) with a random uuid name. The extension comes from the mime, so a caller cannot name the file. The "copy this link" path only accepts `http:`/`https:` urls and refuses localhost, `.internal`, `::1` and the private IPv4 ranges — note this is a check on the hostname text, not on the address it resolves to, see checklist item 9. The Supabase service role key stays server-side (`lib/supabase.ts`).
- Outbound links: everything with `target="_blank"` on the public page carries `rel="noopener noreferrer"`, and admin-authored links (the `[text](url)` markdown in the about text, and a project's "Open project" button) render as a link only when the url starts with `http:`, `https:` or `mailto:` — `javascript:` and `data:` urls are dropped to plain text (`safeUrl` in `app/site.tsx`).
- Cron: `GET /api/keepalive` requires `Authorization: Bearer CRON_SECRET`. The secret is set in Vercel Production and an unauthenticated call answers 401 (checked 2026-07-25). The check is skipped while the env var is missing, so it fails open if the var is ever removed.
- The passphrase and session secret are set in `.env.local` (gitignored) and Vercel env vars. The literal passphrase is intentionally not written in any committed file; the owner plans to rotate it before the real launch.

## Production checklist (before the real launch)
Each item is tagged `[done]`, `[open]` or `[note]` (a standing rule, nothing to build).

1. `[open]` **Rotate the passphrase** and consider storing an argon2/bcrypt hash in the env var instead of plaintext, comparing against the hash.
2. `[done]` **`ADMIN_SESSION_SECRET`** is set in Vercel Production (`vercel env ls production`, checked 2026-07-25), so every instance signs with the same key and a session survives a redeploy. It is set for Preview as well, and `ADMIN_PASSWORD` is set for Production, Preview and Development — so any preview deploy opens the same admin panel with the same passphrase. Drop those two from Preview if a preview url should not be a second door.
3. `[open]` **Move rate limiting to shared storage** (Upstash Redis / Vercel KV) or the edge (Vercel WAF rules), so it survives restarts and covers all serverless instances. For true per-session revocation, store session ids server-side. Return 429 without detail.
4. `[note]` **`x-forwarded-for` trust**: the limiter keys on the first XFF hop. This is safe on Vercel (the platform sets the header). Behind another proxy the first hop is client-controlled — key on a trusted source there.
5. `[note]` **Never commit secrets.** `.env*` is gitignored (except `.env.example`). If a secret ever lands in a commit, rotate it.
6. **Supabase**:
   - `[done]` `CRON_SECRET` is set in Vercel Production, so `/api/keepalive` is no longer open: an unauthenticated `GET https://aimwork.space/api/keepalive` answers 401 (checked 2026-07-25). The cron itself sends the bearer header, see `vercel.json`.
   - `[done]` size and mime limits are enforced in `/api/upload` (25mb, jpeg/png/webp/svg/gif/mp4/webm).
   - `[open]` the `media` bucket is public-read; confirm writes need the service role key and mirror the size/mime limits in the bucket settings, so the API is not the only place they exist.
   - `[open]` if the tables in HANDOFF.md ever land: RLS, readable by anon, writable only by the admin role. (Today the only table is `keepalive`.)
7. **Headers** (`next.config.mjs`, live on aimwork.space):
   - `[done]` HSTS (2 years, includeSubDomains), `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy` (camera / microphone / geolocation off), and `X-Robots-Tag: noindex, nofollow` on `/admin` and `/admin/*`.
   - `[open]` the CSP is `Content-Security-Policy-Report-Only` and has no `report-uri`/`report-to`, so it neither blocks nor collects anything. Fonts and icons are local now, so the only outside hosts left are the exchange API (`open.er-api.com`) and the Supabase storage host. Flipping it to enforcing needs a nonce for the two inline scripts in `app/layout.tsx` (`scrollRestoration` and the JSON-LD block), otherwise `script-src` has to keep `'unsafe-inline'` and the policy buys little. `style-src` also still needs `'unsafe-inline'`: the page styles a lot inline.
8. `[open]` Optionally put `/admin` behind Vercel password protection or its own subdomain as a second layer.
9. `[open]` **Harden the link-import path in `/api/upload`.** The guard matches on the hostname text, so it stops the obvious targets but not a hostname that *resolves* to a private address, and it does not cover `0.0.0.0`, decimal/octal IPv4 forms, IPv4-mapped IPv6, or the IPv6 private ranges. `fetch` also runs with `redirect: 'follow'`, so a public url may redirect to a private one and the guard never sees it. Only the logged-in admin can call this, so it is a second-order risk; the real fix is to resolve the host and check the resolved address, and to follow redirects by hand.
